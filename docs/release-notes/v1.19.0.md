Docuchango 1.19.0 makes documentation fixes atomic by default, adds automatic link and formatting repairs, and reduces validation noise. This release includes all changes since 1.18.1.

## Before you upgrade

- **Fixes are now all-or-nothing.** If validation still finds issues after applying repairs, `docuchango validate` restores the original files and reports the fixes as withheld. Resolve the remaining issues and rerun, or use `--no-atomic` to keep partial fixes. `--dry-run` continues to leave files untouched. ([#86](https://github.com/jrepp/docuchango/pull/86))
- **An empty scan now fails.** A run that finds no documents exits with an error instead of reporting success. Check the repository path and configuration, or pass `--allow-empty` for an intentionally empty project. ([#89](https://github.com/jrepp/docuchango/pull/89))
- **Project IDs and dates receive stricter checks.** Documents must match their governing configuration's `project.id`; empty IDs and the `my-project` placeholder can be repaired automatically, while other mismatches need review. Dates must use `YYYY-MM-DD` or `YYYY-MM-DDTHH:MM:SSZ`. ([#94](https://github.com/jrepp/docuchango/pull/94), [#99](https://github.com/jrepp/docuchango/pull/99))
- **Configured paths stay inside the project by default.** Trusted layouts that intentionally reference external paths can opt in with `security.allow_external_paths: true`. ([#64](https://github.com/jrepp/docuchango/pull/64))

## New repairs and configuration options

- Repair broken internal links when exactly one scanned document matches. Links that leave the repository can be converted to absolute URLs when `project.repository_url` is configured and the target exists on disk. ([#102](https://github.com/jrepp/docuchango/pull/102), [#103](https://github.com/jrepp/docuchango/pull/103))
- Escape prose placeholders that MDX would treat as JSX tags during normal validation. ([#101](https://github.com/jrepp/docuchango/pull/101))
- Normalize CRLF and mixed line endings, remove UTF-8 byte-order marks, and collapse excessive blank lines outside frontmatter and fenced code. ([#95](https://github.com/jrepp/docuchango/pull/95), [#92](https://github.com/jrepp/docuchango/pull/92), [#98](https://github.com/jrepp/docuchango/pull/98))
- Opt into nested-document validation with `structure.scan_subfolders`, with overrides per document type. Numbering-gap reports are also available per type through `report_numbering_gaps`. ([#84](https://github.com/jrepp/docuchango/pull/84), [#100](https://github.com/jrepp/docuchango/pull/100))

## Validation fixes

- Reduce false positives for prose comparisons, valid HTML/JSX, code spans, directory links, links into the repository's source tree, and ADR amendment IDs. Preserve static-asset extensions when checking links. ([#71](https://github.com/jrepp/docuchango/pull/71), [#65](https://github.com/jrepp/docuchango/pull/65))
- Accept `Rejected` as an ADR/RFC status. Generate frontmatter from the configured schema and correctly replace multiline YAML fields. ([#70](https://github.com/jrepp/docuchango/pull/70), [#91](https://github.com/jrepp/docuchango/pull/91), [#88](https://github.com/jrepp/docuchango/pull/88))
- Honor subproject readability settings, resolve relative and symlinked CLI paths consistently, and locate legacy document folders under `docs_roots`. ([#90](https://github.com/jrepp/docuchango/pull/90), [#85](https://github.com/jrepp/docuchango/pull/85), [#97](https://github.com/jrepp/docuchango/pull/97))
